# 惠福星链 · 技术白皮书

## 摘要

惠福星链（Huifu StarChain）是一款深度嵌入公立医院就诊流程的全生命周期健康管理 SaaS 平台。本文档阐述其技术架构、核心设计决策、安全合规方案及性能指标。

---

## 1. 系统架构

### 1.1 总体架构

```
┌─────────────────────────────────────────────────────┐
│                    接入层 (Nginx)                     │
│         HTTPS/TLS 1.3 · 限流 · 静态资源              │
├──────────┬──────────────────┬───────────────────────┤
│ 小程序    │ 企业微信 (Butler) │ 管理后台 (Vue3 SPA)   │
├──────────┴──────────────────┴───────────────────────┤
│                    应用层                             │
│         Spring Boot 3.2 · Java 21                    │
│         Virtual Threads · JPA · JWT                  │
├──────────┬──────────────────┬───────────────────────┤
│  MySQL 8 │     Redis 7      │       MinIO           │
│ (主数据库)│  (缓存/会话/限流) │   (文件/PDF/报告)      │
└──────────┴──────────────────┴───────────────────────┘
```

### 1.2 关键设计原则

| 原则 | 实现 |
|------|------|
| 医疗数据安全 | 手机号/姓名 AES-256加密，身份证号 SHA-256 哈希只存特征值 |
| 数据主权 | 完整医疗数据留院（HIS/EMR），云端仅存脱敏摘要 |
| 家庭维度 | family_id 贯穿全部业务表，一位成员关联即全家庭可见（需授权） |
| 事件溯源 | 审计日志覆盖所有写操作，trace_id 关联分布式追踪 |
| 弹性伸缩 | Systemd 服务管理，Redis 缓存读多写少场景 |

## 2. 数据模型

### 2.1 核心实体关系

```
users (1) ──< family_members >── (1) families
  │                                      │
  ├── (N) health_records ──< lab_reports
  ├── (N) followup_tasks
  ├── (N) package_orders ──< benefit_redemptions
  └── (N) chat_sessions ──< chat_messages
```

### 2.2 数据库选型

- **MySQL 8.0 Community Edition**
  - InnoDB 引擎，行级锁，事务支持
  - utf8mb4 字符集，兼容 emoji 和生僻字
  - JSON 列存储弹性字段（benefits_json, detail_json）
  - FULLTEXT 索引支持知识库全文搜索
  - 原生 hikariCP 连接池，20 最大连接

### 2.3 加密与脱敏

| 字段类型 | 存储方式 | 加密算法 |
|----------|----------|----------|
| 手机号 | AES-256 加密 + SHA-256 哈希 | ECB/PKCS5Padding |
| 真实姓名 | AES-256 加密 | ECB/PKCS5Padding |
| 身份证号 | AES-256 加密 + SHA-256 哈希 | ECB/PKCS5Padding |
| 脱敏姓名 | 如"张*芳"（明文仅存脱敏版本） | - |

## 3. 安全架构

### 3.1 认证与授权

- **JWT (JSON Web Token)**：无状态认证，HMAC-SHA256 签名
- **Token 生命周期**：Access Token 2h，Refresh Token 7d
- **角色模型**：RESIDENT / BUTLER_MEDICAL / BUTLER_SERVICE / HOSPITAL_ADMIN / OPS_ADMIN / SUPER_ADMIN
- **接口级权限**：`@PreAuthorize` + Spring Security 方法级注解

### 3.2 传输安全

```
客户端 ──TLS 1.3──▶ Nginx ──HTTP──▶ Spring Boot API
         (公网加密)        (内网明文)
```

- 全链路 HTTPS，TLS 1.2+ 最低版本要求
- Nginx 反向代理终结 TLS，内网 HTTP 明文
- 医院前置机对接使用专线 + IP 白名单 + Token 认证

### 3.3 合规

- **等保三级**：云端系统通过三级等保认证
- **用户授权**：注册时弹窗单独确认数据授权，可随时撤销
- **审计日志**：全量记录增删改查操作，不可篡改，保留期 ≥ 3年

## 4. 性能设计

### 4.1 性能目标

| 指标 | 目标值 |
|------|--------|
| API 响应时间 (P95) | < 500ms |
| API 响应时间 (P99) | < 2s |
| 并发连接数 | ≥ 10,000 |
| 数据库连接池 | 20 (HikariCP) |
| Redis 缓存命中率 | > 85% |

### 4.2 缓存策略

- **Redis 缓存**：Dashboard KPI 预计算并缓存（5分钟刷新）
- **JWT 无状态**：无需服务端 Session，水平扩展无状态
- **Browser Cache**：前端静态资源强缓存（7天）

### 4.3 数据库优化

- 复合索引覆盖高频查询（user_id + event_date, status + scheduled_date）
- 分页查询全部使用 Pageable，避免全表扫描
- JPA `open-in-view: false` 避免长事务
- 定时任务批量聚合 Dashboard 缓存表

## 5. 与医院系统对接

### 5.1 对接架构

```
荔小福云端 ──HTTPS/专线──▶ 医院前置机（只读中间件）
                                   │
                                   ├── HIS (患者信息、挂号缴费)
                                   ├── LIS (检验报告)
                                   ├── PACS (B超/影像)
                                   ├── EMR (出院小结/手术记录)
                                   └── 五健系统 (筛查结果)
```

### 5.2 数据同步流程

1. 医院系统产生新数据
2. 前置机检测变更 → 推送至云端 API
3. 云端校验签名 → 存入 hospital_gateway_sync 日志
4. 解析数据 → 创建 health_record + lab_report
5. 异常指标判读 → 自动创建 followup_task

### 5.3 安全措施

- 前置机只读接口，不可写回医院系统
- 接口 Token + IP 白名单双重认证
- 传输数据 AES-256 加密
- 完整数据留院，云端只存脱敏摘要

## 6. AI 能力概述

### 6.1 三层 AI 体系

| 层级 | 能力 | 覆盖率 |
|------|------|--------|
| 第一层 | 智能问答库（FAQ 匹配） | 80% 高频问题 |
| 第二层 | 主动推送 + 随访自动化 | 按孕周/月龄/异常指标 |
| 第三层 | 大模型多轮对话（规划中） | 复杂情境理解 |

### 6.2 智能识别

- **意图识别**：自动分类用户问题 → 医疗 / 权益 / 投诉 / 通用
- **情绪识别**：分析消息情感 → 焦虑/愤怒检测 → 自动升级
- **紧急预警**：关键词匹配 → "出血""破水""剧痛"等触发10分钟响应
